# ScanDiff web

Web viewer for ScanDiff (Cal Hacks 13.0). It compares a baseline 3D scan with a later scan and shows a heat map, a histogram and flagged regions. It also includes a demo checkout (shipping and returns) and a rental car timeline.

ScanDiff provides **tamper-evident evidence of condition at handoff**. It does not verify that an item is as advertised. Every payment screen is a demo: **no real payment** takes place, and there is no real Apple Pay or Visa integration.

## Run locally

```bash
cd web
npm install
npm run dev      # http://localhost:3000
npm run build    # production build check
```

By default everything runs on mock data generated in the browser. No backend, database or API key is needed.

## Data modes

Set these in `web/.env.local` (copy `.env.example`). They are read at build time, so rebuild or restart `npm run dev` after changing them.

| Variable | Effect |
| --- | --- |
| `NEXT_PUBLIC_DIFF_API_URL` | Empty: browser mock. Set (e.g. `http://localhost:8000`): call the engine's `POST /diff`. |
| `NEXT_PUBLIC_DIFF_API_MOCK` | `true`: ask the engine for its fixed example (`?mock=true`). The page labels it as an example. |
| `NEXT_PUBLIC_DIFF_UP_AXIS` | `Y` (default) or `Z`, the engine frame's up axis. |

The page always shows where its data came from (browser mock, engine example, or engine).

To run the engine for testing: `cd engine`, install `requirements.txt`, then `uvicorn app.main:app --port 8000`. Note that the engine rewrites the sample GLBs in `engine/static/` on startup.

## Where the teammate integrations plug in

| File | Purpose | Now | Later |
| --- | --- | --- | --- |
| `lib/types.ts` | The web app's own data types | Used by every component | Unchanged |
| `lib/contract.ts` | Engine `DiffResponse` types | Generated by `npm run gen:contract` from `engine/contract/diff_response.schema.json` | Re-run after every contract change |
| `lib/diffClient.ts` | `getDiff(baseId, newId)` | Browser mock, or `POST /diff` mapped onto `DiffResult` | Unchanged |
| `lib/modelLoader.ts` | `loadModel(url)` | GLB (keeps vertex colors) and PLY | Unchanged: the engine converts USDZ to GLB |
| `lib/scanMetadata.ts` | iOS `metadata.json` to `ScanMeta` | Not wired; fixture in `lib/fixtures/` | Use when scans come from Supabase |
| `lib/items.ts` | Item title, price, scan history | Mock catalog | Backend item source |
| `lib/orderStatus.ts` | Checkout status flow | `localStorage` | Driven by real database updates |

## Pages

- `/` home
- `/checkout/mug-001` demo checkout (shipping and returns)
- `/item/mug-001`, `/item/car-001` comparison viewer
- `/item/<id>/evidence` printable dispute evidence

## Deploy to Vercel

1. In Vercel, choose **Add New → Project** and import this GitHub repository.
2. Set **Root Directory** to `web`.
3. Keep the detected Next.js framework and its default build settings. For the browser mock, no environment variables are needed. To use the engine, add `NEXT_PUBLIC_DIFF_API_URL` with a public HTTPS engine URL (a deployed page cannot call `localhost`).
4. Click **Deploy**. Each push to the connected branch creates a new deployment.
